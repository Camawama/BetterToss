## [Unreleased]

### Added
- Other mods' hand-thrown items are charge-thrown from the very first throw (the owner, 2026-10-31: "I thought better toss would work with any thrown projectile by default? It seems like I keep finding more things that need to be allowed to throw with better toss. now it's one of my backport mods that adds the item `ice_caves:ice_ball`"). The IceCaves backport's ice ball is a plain `Item` whose use throws a `ThrowableItemProjectile` showing the ice ball (1.5 blocks a tick, a snowball's speed), so the class test missed it and the learner only knew it after its first, uncharged throw. Now a start-up scan (`server.ThrowableScan`, server config `scanThrowableProjectiles`, on) runs at every world start before anyone throws: each misc-category entity type is created once in the overworld (never spawned, discarded at once) and, when it is a thrown-item projectile, the item it shows is a candidate; the candidate is charge-thrown from then on when it is plainly an item thrown by hand (not a block, not food, nothing held or drawn, and a class of its own overriding `use(Level, Player, InteractionHand)`, matched by parameter and return types since production runs on SRG names), so a mob's spit whose projectile shows some other item stays out. The finds join the known set and are synced to clients with the learned ones, but aren't saved: the scan runs again each start. The `not_throwable` tag and `throwableBlacklist` still win; `Throwables.knownByItself` is the tag/list/class test alone, `Throwables.learnAll` adds the scan's finds. Checked in the main pack (which has IceCaves), owner's JVM: the scan looked at 522 misc entity types, 51 of them thrown-item projectiles, and found 14 hand-thrown items (the ice ball, Galosphere's palladium bomb, Biomancy's toxin grenade and acidic egg, Undergarden's blisterbomb, Spelunkery's stone pebble and eggplant, Vanilla Tweaks' dynamite, the Aether's lightning knife, Alex's Mobs' cockroach ootheca and emu egg, Farmer's Delight's rotten tomato, Quark's parrot egg, Supplementaries' bomb), 17 known already (vanilla's, Enderman Overhaul's pearls, Cardiac's bottle), 20 rejected (mob spits and shards with no use of their own, foods, blocks, a drawn pearl), one type failing to construct, 510 ms; `toss_cardiac` still passes on this jar (its learned round empties the known set and reloads the tag, so the scan's finds don't stand in). Pack harness `toss_iceball` (new, laneless, the main pack): the scan's finds name the ice ball and it is throwable before any throw (both seen), and from the real use key the very first click must leave at the empty bar's power (1.5 x 0.35), a 32-tick hold at the bar's value, a second click at the empty bar's again: those three throws are still to be seen, since the scenario's first two runs gave the player 64 ice balls, which vanilla's item command refuses for an item that stacks to 16, so every click used an empty slot (fixed to the item's max stack), and the third run was stopped by the machine running out of memory.

### Fixed
- Holding Q to fling the selected item no longer drops a second item on the release (the owner, 2026-10-31: "When holding down Q to use better toss to drop an item, sometimes when I release it, it throws the item I charged but also counts as a second Q press and drops a second item as the other item was thrown. It doesn't happen everytime"). Cause: holding a key makes the system repeat it, and each repeat is a click in vanilla's counter; Better Toss sweeps those clicks at the start of every client tick and ignores them while a charge is on, but a repeat that arrived in the same input batch as the release was still uncounted when the release threw, so the next tick's sweep read it as a fresh tap of a key that was already up and dropped an item (as often as a repeat happened to land in the release's frame). Fix: when a charge ends (released or cancelled) the clicks still counted on its key are drained (the drop key for a Q fling, the use key for an item or caught throw: mouse buttons never repeat, a key bound to use could), a drop-key click read in the same client tick a drop charge ended is ignored, and a tap held long enough to repeat (a long `dropHoldTicks`) drains its repeats too. Quick taps are untouched.

- Cardiac's life bottles are charge-thrown like XP bottles (the owner, 2026-10-29: "Cardiac doesn't work with better toss. I should be able to use better toss to throw the life bottles"). The bottle is a plain item whose use throws a projectile of its own, so the class test (anything extending a vanilla throwable item) never saw it; it is now an optional entry in the `bettertoss:throwable` tag.
- Other mods' throwables built the same way are learned from their first throw: when an item's own use throws, at once and without a draw, a projectile showing that same item (the way vanilla throws a snowball or an XP bottle), it is charge-thrown from then on, saved with the world and synced to every client (server config `learnThrowables`, on). Its first throw in a world is the item's own. The `bettertoss:not_throwable` tag and `throwableBlacklist` still win. The network protocol is 3 (a client and server must both have this version).

### Changed
- Tridents are vanilla's again by default: their own draw, throw, Loyalty and Riptide, no charge bar, whatever the tags and lists say. Server config `tridents` (false) takes them over as before: the charge bar, its power, focus and strain apply to a trident throw.

## [1.0.0]

### Added
- Hold-to-charge throws for every throwable item, with an oscillating (or ramping) power bar in the XP bar's slot. A quick click still throws straight away as a weak, uncharged toss (empty-bar power, widest spread), with no throw cooldown, so eggs and snowballs can be spammed; the hold that starts a charge is configurable (`useHoldTicks`, 5 ticks). Tridents charge from the first tick.
- Flick throws: mouse motion at the instant of release bends the throw, with configurable thresholds, strength and caps.
- Focus: quick clicks and early releases have a wide spread that steadies over the first two seconds of the hold, with a slight FOV zoom. Optional one-line tips, off by default.
- Strain: a charge held too long gets shaky, the way a spear does when held out too long. The hand is steady at first, then trembles more and more (from 2 s, fully by 5 s: server `strain.steadyTicks` 40 and `strain.shakyTicks` 100), in first person and on the third-person arm, and the throw scatters by up to 4° more (`strain.maxInaccuracyDegrees`). How much the hand trembles is the client's `strain.handTremble` (1, 0 turns it off). This replaces the old camera and hand shake, which ran the other way (shaky at the start, steadying as you held) and was off by default: `cameraShake`, `cameraShakeDegrees` and `handShake` are gone, and `barShake` now shivers the bar with the strain instead. The tremble, the charge bar and the spread are Camafy's shared hold-to-charge mechanic, the same as Nice Catch's rod casts (needs Camafy 0.1.13).
- Client config migration: settings still on an old default (tips and shakes on, from the first builds) move to the new default; settings you changed are kept.
- First-person wind-up and whip animations, and third-person wind-up, throw and holding poses visible to other players.
- Drop-key flings: tap Q to drop, hold Q to charge a throw of the selected item (Ctrl for the whole stack). Bigger stacks are heavier and fly shorter, with the reachable part of the bar shown.
- Catching: hold the catch key (right-click by default) to catch incoming projectiles; caught projectiles stay projectiles, must be thrown before anything else can be done, and drop in place on logout.
- Generic compatibility: any item that spawns a projectile from its use() is charged, with item/entity tags and config lists for the rest.
- Extensive server and client configuration.
